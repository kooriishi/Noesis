# 「看不懂 · 整体定位」分级重讲策略 (reexplain.overall)

用户对当前代码片段的【整体定位】感到困惑（不清楚它在整个项目中扮演什么角色、上下游是谁）。

## 讲解要求
1. **先给系统鸟瞰图**：用通俗的一句话交代这段代码所在的模块/节点名称、由谁触发调用、处理后的数据流向哪里。
2. **强制使用图事实**：必须依据 ContextPack 中的项目图事实（如 ROS 2 的发布/订阅话题与 Launch 启动关系，或 LLM 应用的路由 → 调用 → 工具链路）说明上下游位置，并附带真实行号引用。
3. **生活化系统类比**：用一个现实生活中的实体协作场景（如机场塔台调度、流水线分拣站）类比该模块在系统中的角色。
4. **按级别调整深度**：
   - Level 1：模块鸟瞰 + 上下游调用/话题流向 + 实体类比。
   - Level 2：降低前提，把涉及的每个模块名和通信概念先用大白话一句话解释，再画出“输入 → 本段代码 → 输出”三步流向。
   - Level 3：列出最多 3 个必须先看懂的前置概念或上游入口文件，建议用户先阅读前置内容。
