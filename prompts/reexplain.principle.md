# 「看不懂 · 底层原理」分级重讲策略 (reexplain.principle)

用户对当前代码片段背后的【设计动机与系统原理】感到困惑（不知道为什么要这样设计、不这样写会出什么问题）。

## 讲解要求
1. **一句直觉类比**：先用一句现实生活中的物理或工程类比建立直觉。
2. **反推设计代价（不这样写会怎样）**：层层下钻回答三个问题：
   - 它在解决什么底层问题（延迟、死锁、内存拷贝、丢包、乱序、幻觉）？
   - 如果去掉这段设计，在真实运行环境下会出现什么故障？
   - 当前项目为什么选择这种权衡（有源码或配置证据则引用，没有则写入 `unknowns`，绝不凭空编造作者意图）。
3. **关联领域知识包（`pack_ref`）**：若涉及已加载的 ROS 2 Humble 或 LLM 应用知识包条目，必须引用对应的 `pack_ref`。
4. **按级别调整深度**：
   - Level 1：直觉类比 + 故障反推 + 知识包原理关联。
   - Level 2：把所有专业术语先用一句话白话解释，再用“问题现象 → 原因 → 代码里的解法”三步讲清。
   - Level 3：列出最多 3 个必须先了解的前置系统/领域原理概念（自动加入复习候选）。
