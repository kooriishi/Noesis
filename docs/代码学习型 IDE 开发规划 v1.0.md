# 代码学习型 IDE 开发规划 v1.0

Oct 18, 2026 · @ikura

## 目标与已确认决策

**目标:做一款自用的桌面 IDE 暂时命名为 NOESIS,专门解决「通用 AI 讲大型项目太泛、没有深度」的问题;七项决策已全部确认,可以进入开发。**

通用 AI 讲不深,原因有三,整个设计都围绕它们展开:

- 它只看到被塞进上下文的片段,讲不出项目的整体结构和阅读顺序。
- 它一次性回答,没有「先规划、再逐层钻深」的过程,结果要么太泛,要么冗长堆术语。
- 看不懂的点分散在整体、逻辑、语法、原理四类,它不区分,也不记得你卡在哪里。

| 决策 | 结论 | 说明 |
| --- | --- | --- |
| 1 底座 | Tauri 2,Windows 与 Linux 都必须可用 | 两端分别用 WebView2 与 WebKitGTK 渲染,双端从第一个里程碑起同步验证 |
| 2 编辑器内核 | CodeMirror 6 | 行内装饰和块级组件容易做「解读气泡」;官方 LSP 客户端已覆盖补全、悬停、跳转、引用、重命名;比 Monaco 轻 |
| 3 首个验证项目 | 稍后在开发文档中给出 | 最晚在 M0 开始前需要,用来压测索引和评估解读质量 |
| 4 商业策略 | 无,先自用 | 不分发则许可证约束基本不触发;日后若要分发,再重新评估 |
| 5 模型策略 | 自带密钥,支持自定义接口地址 | 自定义地址可以接公司内网或本地的兼容接口 |
| 6 解读智能体提示词 | 以现有「代码深度导读专家」为起点迁移,重写为分层输出 | 保留角色定位,改成四层视角加渐进展开,避免一次输出过长、术语成堆 |
| 7 首发人群 | 你自己,学习公司的大型项目 | 重点是私有代码的外发控制,以及公司环境下 Windows 与 Linux 都能跑 |

自带密钥意味着代码片段会发给你选定的模型服务;公司代码是否允许外发,需要你先确认公司规定,规划里已把「外发控制」作为 P0 能力。

## 深度解读引擎

**让 AI 讲出深度的办法是「结构先于讲解」:先用静态分析算出项目的真实结构,再让模型在这个结构上逐层讲,每一句话都要有源码依据。** 这是整个产品最重要的部分,也是和通用 AI 聊天的根本区别。

&#91;embedded content: 解读引擎流水线 · 本地计算与模型参与两段,1 个回流\]

上排由代码确定性地算出,下排才交给模型;模型讲的每一句话都落在上排算出的结构上,而不是凭印象展开。

1. **结构先于讲解。** 用 tree-sitter 和 LSP 的引用信息建出模块图、调用图和入口点。阅读顺序由图计算:从入口出发,按依赖关系和被引用次数排序。模型只负责命名和润色,不凭感觉排顺序。
2. **四层视角。** 每个学习单元固定产出四类解读:整体(职责、位置、数据流),逻辑(控制流、状态、边界条件、为什么这样设计),语法(语言特性、惯用写法、宏与泛型),原理(背后的算法、协议、系统机制)。
3. **先规划、再钻深。** 按「项目、模块、调用链、函数」逐层下钻,上一层的摘要作为下一层的上下文,保证局部讲解不丢全局。
4. **先短后长。** 每张解读卡片先给一句话和三五行要点,点「展开」才出细节;术语第一次出现时附一句人话解释。深度来自层次,不来自篇幅。
5. **「看不懂」标记。** 选中任意代码,一键标记属于整体、逻辑、语法、原理中的哪一类。系统据此换讲法:换类比、给最小示例、补前置概念,并把标记记入学习档案,后面的练习优先覆盖。
6. **依据与自检。** 每条断言附源码位置。生成之后有一步校验,检查引用的文件、行号和调用关系真实存在;把握不足的地方明说,不硬编。
7. **原理溯源。** 遇到框架或算法背后的原理,生成一张「概念卡片」,链接到所有用到它的位置,避免每处重复讲。

## Windows 与 Linux 双端落地

**两端都可用的关键,是把差异收在渲染引擎、打包、系统集成三处,并让每个里程碑都在两个系统上各验收一遍。**

| 项目 | Windows | Linux | 应对 |
| --- | --- | --- | --- |
| 渲染引擎 | WebView2;Windows 11 与多数 Windows 10 已预装,否则要装运行时 | WebKitGTK;Tauri 2 要求 4.1 版,例如 Ubuntu 22.04 及以上 | 前端不依赖只有 Chromium 才有的特性;CI 里双端跑界面冒烟测试 |
| 安装包 | NSIS 的 .exe 或 WiX 的 .msi | .deb、.rpm、AppImage | 自用阶段先出 Windows 的 .msi 与 Linux 的 AppImage、.deb |
| 外部程序(语言服务器、git) | 可执行文件带 .exe 或 .cmd 后缀 | 通常直接在 PATH 里 | 统一由 Rust 内核启动子进程,路径解析封装成一层 |
| 路径与换行 | 反斜杠、盘符、CRLF | 正斜杠、LF | 内部一律用规范化路径,存储里不带平台差异 |
| 文件监听 | 目录变更通知 | 监听句柄有上限,大仓库容易触顶 | 默认忽略依赖和构建目录,监听失败时退化为手动刷新 |
| API 密钥存储 | 系统凭据管理器 | Secret Service(如 GNOME Keyring、KWallet) | 密钥放系统钥匙串,不写明文配置;无钥匙串的环境退化为加密文件 |
| 临时子窗口 | 原生多窗口 | 置顶、拖动在不同桌面环境表现可能不同 | 悬浮形态先做成应用内面板,独立窗口作为可选形态 |

**验证方式**

- CI 矩阵:每次提交在 Windows 与 Ubuntu 上各构建一次并出安装包。
- 每个里程碑结束,在你实际使用的 Windows 和 Linux 发行版上各走一遍验收清单。
- 公司环境的差异(代理、证书、禁用外发)放进 M5 单独验证。

## 工程结构与数据模型

**单仓库、前后端分离:Rust 内核按功能拆成独立 crate,前端按界面区域拆包,两边只通过一组命令和事件通信。**

```text
repo/
├─ src-tauri/crates/     Rust 内核
│  ├─ project/           导入、文件树、监听、忽略规则
│  ├─ indexer/           tree-sitter 解析、符号与引用、项目图
│  ├─ lsp/               语言服务器进程管理与消息转发
│  ├─ llm/               模型网关:多提供方适配、流式输出、外发过滤
│  ├─ learn/             学习单元、解读卡片、练习、复盘调度
│  ├─ runner/            草稿运行(子进程)
│  └─ store/             SQLite 访问与迁移
├─ src/                  前端
│  ├─ shell/             整体布局、命令面板、主题
│  ├─ editor/            CodeMirror 6 扩展:解读气泡、阅读标记
│  ├─ sidebar-project/   文件、地图、路线
│  ├─ sidebar-ai/        聊天、解读、练习
│  └─ scratch/           临时子窗口
├─ prompts/              智能体提示词(纯文本,版本化)
└─ eval/                 解读质量评测集与脚本
```

**数据模型(SQLite)**

| 表 | 存什么 | 关键字段 |
| --- | --- | --- |
| projects、files | 已导入项目与文件元数据 | 路径、语言、内容哈希、索引版本 |
| symbols、edges | 符号,以及调用与引用关系 | 名称、种类、起止位置、关系类型 |
| modules | 模块划分 | 名称、成员、摘要 |
| summaries | 分层摘要:项目、模块、文件、函数 | 层级、目标 id、文本、依据哈希 |
| units | 学习单元与阅读顺序 | 所属模块、顺序、状态 |
| cards | 解读卡片 | 单元、视角(整体 / 逻辑 / 语法 / 原理)、内容、源码引用 |
| marks | 「看不懂」标记 | 位置、类别、时间 |
| exercises、attempts | 练习题与作答记录 | 题型、参考答案及其源码依据、评分、下次复习时间 |
| notes | 笔记与草稿 | 类型、内容、关联位置 |

summaries 通过内容哈希关联源码,文件改动后只重算受影响的摘要,这是大仓库能负担得起的前提。

**核心命令**

| 命令 | 作用 |
| --- | --- |
| import\_project、index\_status | 导入项目、查看索引进度 |
| get\_project\_map、get\_reading\_route | 取项目地图与阅读路线 |
| explain、expand\_card | 对选区按指定视角解读、展开卡片细节 |
| mark\_confusion | 记录「看不懂」标记并触发换讲法 |
| generate\_exercises、grade | 出题与批改 |
| list\_due\_reviews | 取今天该复习的题 |
| llm\_send(流式事件) | 统一的模型调用入口,所有外发都经过它 |

**外发控制(P0)**

所有发给模型的内容都经过 llm 这一个出口:默认排除 .env、密钥和证书类文件,限制单次内容量,支持按正则脱敏,并可在发送前预览将要发出的内容。

## 评测与质量

**用一套固定评测集衡量解读质量:围绕首个验证项目准备一批问题和参考要点,每次改提示词或流水线都跑一遍,分数不降才合入。**

**评测集怎么建**

- 题目优先取你自己真实看不懂的点,整体、逻辑、语法、原理四个视角各准备 5 到 10 题。
- 每题由你写出 3 到 5 条参考要点,作为「讲到了什么才算讲对」的标准。
- 同一批问题再原样问一次通用 AI(直接粘贴相关代码)作为对照;这个产品存在的理由,就是要在这份对照上明显胜出。

**评分维度**

| 维度 | 含义 | 判定方式 |
| --- | --- | --- |
| 准确 | 断言与源码一致 | 自动:引用校验通过率 |
| 覆盖 | 命中了多少参考要点 | 模型对照要点打分,抽样人工复核 |
| 深度 | 讲到「为什么」和原理,而不只是复述代码 | 人工按三档打分 |
| 可读 | 先短后长、术语有解释、没有堆砌 | 人工打分,加卡片长度上限检查 |
| 可行动 | 读完能答对对应的练习题 | 练习正确率 |

质量线不凭空定:M2 开始时先跑一版基线,再把质量线设在基线之上,并保证「相对通用 AI 对照」持续领先。

**日常反馈回流**

每张解读卡片带一组一键标签:有用、太泛、太长、有误。被标成太泛或有误的案例自动加入评测集,评测集随使用越来越贴近你的真实卡点。

**工程质量**

- 索引与解析用几个固定的小仓库做快照测试,防止改解析器时悄悄变样。
- 练习题的参考答案必须能在源码里找到依据,上线前抽样人工复核。
- Windows 与 Ubuntu 双端 CI 每次提交都跑构建和界面冒烟测试。

## 风险与应对

**最大的两个风险是「解读仍然泛」和「公司代码外发」,前者靠评测集和引用校验兜底,后者靠外发控制和事先确认规定。**

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 解读仍然泛或有误 | 产品失去存在价值 | 固定评测集加通用 AI 对照;引用校验;先短后长 |
| 公司代码外发 | 合规风险 | 先确认公司规定;外发控制、发送预览、审计日志;必要时只接内网模型 |
| 大仓库索引慢、占内存 | 导入时界面卡顿 | 后台增量索引;先出目录级地图再补符号级;M1 用验证项目压测 |
| 语言覆盖不足 | 首个项目的语言解析不全 | M1 只覆盖首个验证项目的语言,其余按需追加 |
| 模型调用成本高 | 分层摘要消耗大 | 按需生成、缓存、哈希失效;摘要用较便宜的模型,解读用较强的模型,按任务类型分别配置 |
| WebKitGTK 渲染差异或性能 | Linux 端体验差 | 双端 CI;前端避免只在 Chromium 才有的特性;M0 就验证大文件滚动 |
| Linux 无系统钥匙串 | API 密钥无处安全存放 | 退化为加密文件,并在设置里明示 |
| 范围膨胀 | 做不完 | 严守里程碑;M4、M5 的内容可以后移 |
| 单人开发 | 进度不可控 | 每个里程碑结束都能独立使用:M1 起就能当项目地图工具用 |
